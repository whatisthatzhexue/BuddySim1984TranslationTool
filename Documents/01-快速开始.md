# 快速开始

本文从零开始，带你完成环境准备、资源导出、单章翻译和回写校验。第一次使用时建议完整走一遍 `level3`，再批量处理其他资源。

> 开始前请备份：复制整个 `Projects/<项目名>/`；如果要更新游戏，再复制一份 `Buddy Simulator 1984_Data/data.unity3d`。

## 1. 环境准备

### 1.1 Python

需要 Python 3（建议 3.8 及以上），并安装 `requests`：

```bat
python --version
pip install requests
```

如果提示 `'python' 不是内部或外部命令`，请安装 Python 并勾选“Add Python to PATH”，或用 `py -3` 代替 `python`（同时修改 `Functions\-py.bat` 中的 `python`）。

### 1.2 外部工具

| 工具 | 用途 | 是否必需 |
| --- | --- | --- |
| UABE（Unity Asset Bundle Extractor）或 AssetStudio | 导出 MonoBehaviour/JSON/TextMesh，最后回封 `data.unity3d` | 必需 |
| Notepad++ | `open`、`change` 默认调用 | 可选（可改用记事本） |
| Microsoft Edge | `web` 命令打开有道词典 | 可选 |
| 百度翻译开放平台账号 | `TL.py` / `T.py` 机器翻译 | 可选 |

### 1.3 修改本机绝对路径

以下文件含有作者本机路径，换机器后必须按实际情况修改（用文本编辑器打开即可）：

| 文件 | 路径内容 | 修改建议 |
| --- | --- | --- |
| `Functions/open.bat` | `D:\Program Files\Notepad++\notepad++.exe` | 改成你的 Notepad++ 路径，或换成 `notepad.exe` |
| `Functions/change.bat` | 同上 | 同上 |
| `Functions/web.bat` | `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` | 改成你的浏览器路径 |
| `Functions/update.bat` | `C:\Users\用户\Desktop\Translate\...\Buddy Simulator 1984_Data\` | 改成你的游戏数据目录 |
| `PythonExpansion/UPDATE.py` | `C:\Users\用户\Desktop\Translate\BS1984-3_2_4\Buddy Simulator 1984_Data\` | 改成你的游戏数据目录 |

> 路径中如果包含空格，`开始.bat` 的命令分发会把它拆开；这些脚本内部用引号包住了路径，所以脚本本身可以处理空格，但你在命令行里传参时仍要避免空格。

### 1.4 创建运行时目录

在仓库根目录创建：

```text
Temp\
PythonExpansion\Documents\
```

`Temp\` 用来放临时文件，多个脚本会写入并清空它；`PythonExpansion\Documents\` 用来放 `Textsign.txt`、`Banlist.txt` 和修订记录。

项目创建后还要创建 `Workspace\` 根目录：`save` 只会创建 `Workspace\行数\`，如果 `Workspace\` 本身不存在，写 `X文本.txt` 会失败。

### 1.5 配置百度翻译（可选）

1. 在[百度翻译开放平台](https://api.fanyi.baidu.com/)申请通用翻译 API，获取 APPID 和密钥。
2. 编辑 `PythonExpansion/APIs/BaiduAPI.txt`：

```json
{
	"APPID": "你的APPID",
	"APPKEY": "你的密钥"
}
```

不配置也能做纯人工翻译和翻译记忆；只有 `TL.py` / `T.py` 需要它。

## 2. 建立项目并导出资源

### 2.1 创建项目目录

```text
Projects\
└─ Steam324\
   ├─ MonoBehaviour_All\
   ├─ Json\
   ├─ TextMesh\          # 可选
   ├─ MonoBehaviour\     # 由 filter 生成
   ├─ Json_Collected\    # 由 collect 生成
   ├─ Workspace\         # 需先手动创建；save 写入
   ├─ WordLib\           # 由 wordlib 生成
   ├─ TextLib\           # 由 textlib 生成
   └─ Renamed\           # 由 RENAME 生成
```

也可以在 `开始.bat` 提示符下用 CMD 内建命令创建：

```bat
md Projects\Steam324
md Projects\Steam324\MonoBehaviour_All
md Projects\Steam324\Json
md Projects\Steam324\Workspace
```

### 2.2 用 UABE / AssetStudio 导出

以 UABE 为例（不同版本菜单名称略有差异）：

1. 打开游戏目录下的 `Buddy Simulator 1984_Data/data.unity3d`。
2. 选中 MonoBehaviour 资源，导出 **文本 Dump** 到 `Projects/Steam324/MonoBehaviour_All/<资源>/`。
3. 选中同一批资源，导出 **JSON Dump** 到 `Projects/Steam324/Json/<资源>/`。
4. 如有 TextMesh 文本，导出到 `Projects/Steam324/TextMesh/<资源>/`。

`<资源>` 是资源分组名，建议与游戏资源名一致，例如：

```text
MonoBehaviour_All/level3/
MonoBehaviour_All/sharedassets0.assets/
Json/level3/
Json/sharedassets0.assets/
TextMesh/level3/
```

工具依赖以下命名约定，**不要手动改名**：

```text
MonoBehaviour_All/<资源>/<pathID>-<名称>.txt
Json/<资源>/unnamed asset-<资源>-<pathID>.json
```

- `collect` 取 MonoBehaviour 文件名中第一个 `-` 前的数字作为 pathID，去匹配 `Json` 中的 `unnamed asset-<资源>-<pathID>.json`。
- 如果你的导出工具生成的文件名不同，需要调整 `PythonExpansion/COLLECT.py` / `RENAME.py` 的前缀解析逻辑，或先批量改名。

### 2.3 选择当前项目

启动 `开始.bat`（双击，或在 `cmd` 中执行）：

```bat
开始.bat
```

在 `指令:` 提示符下输入：

```text
manage Steam324
```

成功后，标题下方会显示 `当前工作目录:Projects\Steam324\`。`manage` 要求 `Projects\Steam324\` 已存在。

## 3. 生成 Textsign 与 Banlist（Python 版必需）

批处理版 `filter`/`save` 使用硬编码字段和 `黑名单.txt`，不需要本节；Python 版 `FILTER.py`/`SAVE.py` 需要下面两个文件。

### 3.1 生成 Textsign.txt

```text
-py PREFIX_CATCH
```

按提示直接回车（该脚本不使用参数）。它会扫描 `MonoBehaviour_All/`，把发现的字符串字段写入：

```text
PythonExpansion\Documents\Textsign_catch.txt
```

打开该文件，格式如下：

```text
string text=Hello there.
string data=Some data
string id=Dialogue_01
string otherObjectName=Buddy
```

审阅并保留真正需要翻译的字段（通常是 `string text`、`string data`、`string targetString` 等），删除 `string id`、`string otherObjectName` 以及其他非对话字段——它们如果留在白名单里，`SAVE.py` 会当成可翻译行，而不是 `备注`。

把整理后的内容另存为：

```text
PythonExpansion\Documents\Textsign.txt
```

格式是每行 `string <字段名>=<样例>`，脚本只取 `=` 左侧。

### 3.2 生成 Banlist.txt

`Banlist.txt` 用来跳过非对话文本，每行一个**小写**的首词。可以从 `黑名单.txt` 起步：

```text
pause
freeze
event
[event
,
},
```

保存为：

```text
PythonExpansion\Documents\Banlist.txt
```

`FILTER.py` / `SAVE.py` 会取文本值的第一个空格分隔词，转小写后与此列表比较；命中则跳过。

## 4. 跑通 level3

下面给出批处理版和 Python 版两条路线。第一次建议先用批处理版确认资源结构，再切换到 Python 版处理大文件。

### 4.1 路线 A：批处理版

在 `开始.bat` 中依次执行：

```text
clearmono level3
filter level3
collect level3
save level3
open level3
```

| 步骤 | 预期结果 |
| --- | --- |
| `clearmono level3` | 按 `清除名单.txt` 删除 `MonoBehaviour_All/level3` 中无关类型的 `.txt`；输出 `已清除 ... 个...` |
| `filter level3` | `MonoBehaviour/level3/` 中出现含可翻译文本的文件；输出通过/未通过进度和最终数量 |
| `collect level3` | `Json_Collected/level3/` 中出现 `<pathID>-<名称>.json`；若缺失会列出文件 |
| `save level3` | 生成 `Workspace/level3文本.txt` 与 `Workspace/行数/level3` |
| `open level3` | 生成 `Workspace/level3文本翻译.txt` 并用 Notepad++ 打开 |

> `filter` 和 `save` 会使用 `Temp\`。如果 `Temp\` 不存在，先手动创建，否则可能全部判为“未通过”。`save` 还要求 `Projects/Steam324/Workspace/` 已存在。

### 4.2 路线 B：Python 版

先确认 `Textsign.txt`、`Banlist.txt` 已按第 3 节准备好，然后在 `开始.bat` 中执行：

```text
-py FILTER level3
-py COLLECT level3
-py SAVE level3
open level3
```

或者直接在 `cmd` 中（仍在仓库根目录）：

```bat
python PythonExpansion\FILTER.py "Projects\Steam324" level3
python PythonExpansion\COLLECT.py "Projects\Steam324" level3
python PythonExpansion\SAVE.py "Projects\Steam324" level3
```

Python 版输出与批处理版格式兼容，后续步骤可以混用。

## 5. 翻译

### 5.1 人工翻译

编辑：

```text
Projects/Steam324/Workspace/level3文本翻译.txt
```

规则：

- 保留 `当前文件:` 和 `备注:` 行原样；
- 只改以制表符开头的行（或含 `\` 的整行 JSON 行）；
- **不要增加或删除行**，否则 `load` 的行号会对不上；
- 文件保存为 UTF-8（无 BOM）。

### 5.2 百度机翻初稿（可选）

在 `开始.bat` 中：

```text
-py TL level3
```

或直接运行：

```bat
python PythonExpansion\TL.py "Projects\Steam324" level3
```

它会读取 `level3文本翻译.txt`，把符合句末标点规则的行送去百度翻译，输出：

```text
Projects/Steam324/Workspace/level3文本翻译_baidu.txt
```

机翻是初稿，不会覆盖人工译文。若 API 未配置、网络失败或额度不足，会报错或得到未翻译结果，详见 [04-常见问题.md](04-常见问题.md)。

### 5.3 翻译记忆

人工译文完成后：

```text
wordlib level3
usewordlib level3
```

- `wordlib` 从 `level3文本.txt` 与 `level3文本翻译.txt` 的对应行构建 `Projects/Steam324/WordLib/<md5>`。
- `usewordlib` 用词库生成译文：如果 `level3文本翻译.txt` 已存在，输出 `level3_Translated.txt`；否则输出 `level3文本翻译.txt`。
- 词库是精确匹配；英文行改动一个字符就会失效。

也可以使用 Python 版：

```text
-py WORDLIB level3
-py USEWORDLIB level3
```

## 6. 回写 JSON 并校验

### 6.1 load

```text
load level3
```

如果 `Workspace/level3*.txt` 有多个文件，脚本会提示选择；输入不含后缀的文件名，例如 `level3文本翻译` 或 `level3_Translated`。

输出：

```text
Projects/Steam324/Workspace/level3/<pathID>-<名称>.json
```

`load` 按 `Workspace/行数/level3` 中的行号，把译文替换回对应 JSON 行的字符串值。

### 6.2 examine

```text
examine level3
```

它用 `fc` 对比 `Workspace/level3/` 与 `Json_Collected/level3/` 中的同名文件，报告差异数量。预期差异应只出现在你翻译过的字符串上。

> 如果你的 Windows 是中文版，`fc` 的正常提示可能被本地化为中文，而 `examine.bat` 只识别英文 `no differences encountered`，可能出现“通过数 0”的误报。此时直接查看 `fc` 输出，或用第 7 节的 JSON 校验方法。

### 6.3 验证 JSON

可以用 Python 检查生成文件是否为合法 JSON：

```bat
python -m json.tool "Projects\Steam324\Workspace\level3\0-Dialogue.json" >nul
```

批量检查（cmd）：

```bat
for %f in ("Projects\Steam324\Workspace\level3\*.json") do @python -m json.tool "%f" >nul || echo 损坏: %f
```

### 6.4 rename-a

批处理版需要两个参数：

```text
rename-a Workspace level3
```

输出到 `Projects/Steam324/Workspace/level3_renamed/unnamed asset-level3-<pathID>.json`。

Python 版：

```text
-py RENAME level3
```

按提示选择 `1`（Workspace）或 `2`（Json_Collected）。推荐选 `1`，输出到：

```text
Projects/Steam324/Renamed/level3_renamed/unnamed asset-level3-<pathID>.json
```

如果目标目录已存在，Python 版会追加 `(1)`、`(2)`，避免覆盖。

## 7. 回封与更新游戏

1. 用 UABE/AssetStudio 打开原始 `data.unity3d`。
2. 用 `Renamed/<资源>_renamed/` 中的 JSON 替换对应资源（具体操作按你使用的工具版本）。
3. 重新打包为 `data.unity3d`（或先导出为 `data1.unity3d`）。
4. 关闭游戏，备份原文件，再执行更新：

- 如果新文件名为 `data1.unity3d`，修改 `Functions/update.bat` 中的路径后运行：

```text
update
```

- 如果新文件名为 `data.unity3d-mod`，修改 `PythonExpansion/UPDATE.py` 中的游戏路径后运行：

```text
-py UPDATE
```

> 回封是外部工具步骤，本仓库不包含 UABE/AssetStudio，也不自动完成资源替换。

## 8. 批量处理

在 `开始.bat` 中：

```text
auto 3-12 0-5
```

表示对 `level3` 到 `level12`、`sharedassets0.assets` 到 `sharedassets5.assets` 依次执行 `clearmono` + `filter`（批处理版）。

```text
auto-t 3-12 0-5
```

表示对同样范围执行 `TL.py` 机翻。注意：

- `auto-t` 要求每个资源已有 `Workspace/<资源>文本翻译.txt`，否则 `TL.py` 会报错；
- 它会把所有控制台输出重定向到 `文本们.txt`（覆盖旧内容），在中文 Windows 下该文件通常是 GBK 编码；
- `auto-t.bat` 中的 `save`、`usewordlib` 调用是注释掉的，需要你另外执行。

Python 版的批量筛选可以用 `CODING` 手动组合，例如：

```text
-py CODING
```

然后输入：

```text
FILTER(level3);FILTER(level4);FILTER(level5)
```

按 `.` 结束并执行。

## 9. 单章完成检查清单

- [ ] `MonoBehaviour/level3` 中文件数量合理，没有把明显非文本资源放进来。
- [ ] `Json_Collected/level3` 数量与 `MonoBehaviour/level3` 一致，没有“缺少文件”。
- [ ] `Workspace/level3文本.txt` 与 `level3文本翻译.txt` 行数一致。
- [ ] `Workspace/行数/level3` 的行号数量与可翻译行数量一致。
- [ ] `load` 生成的 JSON 数量与 `Json_Collected` 一致。
- [ ] `examine` 的差异只出现在目标字符串上。
- [ ] 生成 JSON 能通过 `python -m json.tool`。
- [ ] `rename-a` 输出目录中的文件名符合 `unnamed asset-level3-<pathID>.json`。
- [ ] 已备份原始 `data.unity3d`。
