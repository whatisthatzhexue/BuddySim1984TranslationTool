# 工作流与数据结构

本文说明工具链的每个阶段、中间文件的格式，以及几个容易出错的实现细节。命令参数请看 [02-命令参考.md](02-命令参考.md)。

## 1. 全流程

| 阶段 | 命令 | 主要输入 | 主要输出 | 检查点 |
| --- | --- | --- | --- | --- |
| 导出 | UABE/AssetStudio | `data.unity3d` | `MonoBehaviour_All/`、`Json/`、`TextMesh/` | 文件名符合约定 |
| 清理 | `clearmono` | `MonoBehaviour_All/<资源>/`、`清除名单.txt` | 原地删除无关文件 | 备份后再执行 |
| 筛选 | `filter` / `FILTER.py` | `MonoBehaviour_All/<资源>/` | `MonoBehaviour/<资源>/` | 数量合理 |
| 收集 | `collect` / `COLLECT.py` | `MonoBehaviour/`、`Json/` | `Json_Collected/<资源>/` | 无缺失文件 |
| 导出文本 | `save` / `SAVE.py` | `Json_Collected/<资源>/` | `Workspace/<资源>文本.txt`、`Workspace/行数/<资源>` | 行数与文本一致 |
| 翻译 | `open`、编辑器、`TL.py` | `文本.txt` | `文本翻译.txt`、`文本翻译_baidu.txt` | 不增删行 |
| 记忆 | `wordlib` / `WORDLIB.py` | 原文 + 人工译文 | `WordLib/<md5>` | 行数一致 |
| 应用记忆 | `usewordlib` / `USEWORDLIB.py` | 原文/译文 + `WordLib/` | `_Translated.txt` 或 `文本翻译.txt` | 命中率合理 |
| 回写 | `load` / `LOAD.py` | 译文本 + `行数/<资源>` | `Workspace/<资源>/*.json` | JSON 合法 |
| 校验 | `examine` | 生成 JSON + 原始 JSON | 控制台报告 | 只改目标字符串 |
| 重命名 | `rename-a` / `RENAME.py` | `Workspace/<资源>/` | `Renamed/<资源>_renamed/`（PY）或 `Workspace/<资源>_renamed/`（BAT） | 名称符合回封工具 |
| 回封 | UABE/AssetStudio | 重命名后的 JSON | `data.unity3d` | 备份原文件 |
| 更新 | `update` / `UPDATE.py` | 新 `data.unity3d` | 游戏数据目录 | 关闭游戏 |

## 2. 工作区目录

```text
Projects/<项目名>/
├─ MonoBehaviour_All/<资源>/<pathID>-<名称>.txt   # UABE 文本 dump（输入）
├─ Json/<资源>/unnamed asset-<资源>-<pathID>.json # UABE JSON dump（输入）
├─ TextMesh/<资源>/*.txt                          # TextMesh dump（可选）
│
├─ MonoBehaviour/<资源>/<pathID>-<名称>.txt       # filter 生成
├─ Json_Collected/<资源>/<pathID>-<名称>.json     # collect 生成
├─ Workspace/
│  ├─ <资源>文本.txt                              # save 生成
│  ├─ <资源>文本翻译.txt                          # open/人工翻译
│  ├─ <资源>文本翻译_baidu.txt                    # TL.py 生成
│  ├─ <资源>_Translated.txt                       # usewordlib 生成（可选）
│  ├─ 行数/<资源>                                 # save 生成
│  ├─ <资源>/<pathID>-<名称>.json                 # load 生成
│  └─ <资源>_renamed/                             # rename-a 批处理版生成（可选）
│
├─ WordLib/<md5>                                  # wordlib 生成
├─ TextLib/<md5>                                  # textlib 生成
└─ Renamed/<资源>_renamed/                        # RENAME 生成
   └─ unnamed asset-<资源>-<pathID>.json
```

需要手动创建的目录：

- `Projects/<项目名>/`、`Projects/<项目名>/MonoBehaviour_All/`、`Projects/<项目名>/Json/`（导出前）；
- `Projects/<项目名>/Workspace/`（`save` 不会创建 Workspace 根目录）；
- 仓库根目录的 `Temp/`；
- `PythonExpansion/Documents/`（Python 版配置）。

其余目录由对应命令创建。

## 3. 资源命名与配对

### 3.1 MonoBehaviour 文本 dump

UABE/AssetStudio 导出的文本 dump 文件名形如：

```text
<pathID>-<名称>.txt
```

例如：

```text
123-Dialogue.txt
456-SomeObject.txt
```

`collect` / `COLLECT.py` 取第一个 `-` 前的数字作为 pathID：

```text
123-Dialogue.txt  →  pathID = 123
```

如果文件名中没有 `-`，该文件会被跳过。

### 3.2 JSON dump

JSON dump 文件名形如：

```text
unnamed asset-<资源>-<pathID>.json
```

例如：

```text
unnamed asset-level3-123.json
```

`collect` 用 pathID 把两者配对，输出：

```text
Json_Collected/level3/123-Dialogue.json
```

### 3.3 资源名

`<资源>` 同时是目录名和命令参数，必须一致。常见值：

- `level3`、`level4`……对应关卡；
- `sharedassets0.assets`、`sharedassets1.assets`……对应共享资源包。

`auto` / `auto-t` 的参数 `3-12` 会被解释为 `level3` 到 `level12`；`0-5` 会被解释为 `sharedassets0.assets` 到 `sharedassets5.assets`。

## 4. 筛选逻辑

### 4.1 `清除名单.txt`

`clearmono` 使用的类型名单，每行一个 MonoBehaviour 类型名，例如：

```text
SpriteLayerInfo
MessageBox
Image
```

`clearmono` 遍历 `MonoBehaviour_All/<资源>/`，按文件名中 `-` 之后的部分匹配这些类型名，命中则删除文件。

### 4.2 批处理版 `filter`

`Functions/filter.bat` 不依赖 `Textsign.txt`，它硬编码识别三类字段：

```text
string text = "..."
string data = "..."
string targetString = "..."
```

取字符串值的第一个空格分隔词，与 `黑名单.txt` 比较；只要某个值不在黑名单中，整个文件就通过。

`黑名单.txt` 的典型内容：

```text
pause
freeze
event
[event
,
},
```

这些是“看起来像文本、实际不是对话”的首词，例如事件脚本片段。

### 4.3 Python 版 `FILTER.py`

Python 版更通用：

- `PythonExpansion/Documents/Textsign.txt`：字段白名单，每行 `string <字段名>=<样例>`；
- `PythonExpansion/Documents/Banlist.txt`：首词黑名单，每行小写；
- 对每个文本 dump，逐行去掉制表符，按 ` = ` 拆分；
- 若字段名在 `Textsign` 中，取引号内的值，按空格拆词，去掉空词；
- 若第一个词的小写不在 `Banlist` 中，则文件通过；
- 结果复制到 `MonoBehaviour/<资源>/`。

`FILTER.py` 只有在直接调用且传入第三个参数 `1` 时才处理全部子目录：

```bat
python PythonExpansion\FILTER.py "Projects\Steam324" all 1
```

### 4.4 `Textsign.txt` 怎么来

`PREFIX_CATCH.py` 扫描 `MonoBehaviour_All/`，对每个 `string <字段>` 行记录字段名和样例，写入：

```text
PythonExpansion/Documents/Textsign_catch.txt
```

然后人工筛选：

- 保留 `string text`、`string data`、`string targetString` 等对话字段；
- 删除 `string id`、`string otherObjectName` 等字段（否则 `SAVE.py` 会把它们当翻译行，而不是 `备注`）；
- 保存为 `Textsign.txt`。

`SAVE.py` 读入后会为每行加 `1 ` 前缀，去匹配 JSON 键 `1 string text`；`FILTER.py` 则直接用左侧字段名匹配文本 dump 中的 `string text`。

## 5. `save` 的输出格式

### 5.1 `X文本.txt`

示例（`\t` 表示制表符）：

```text
当前文件:Projects\Steam324\Json_Collected\level3\123-Dialogue.json
备注:	已经检测到Buddy消息
	Hello, [PLAYER]!
	Would you like to learn more?
备注:id:Dialogue_01
备注:物体名:Buddy
当前文件:Projects\Steam324\Json_Collected\level3\124-Other.json
	Another line.
```

规则：

| 行类型 | 含义 | 是否翻译 |
| --- | --- | --- |
| `当前文件:<path>` | 后续行属于哪个 JSON | 否 |
| `备注:...` | Buddy 检测、id、物体名等提示 | 否 |
| 以制表符开头 | 普通字符串值 | 是 |
| 含 `\` 的原始 JSON 行 | 含转义符的字符串，需整行处理 | 是（整行） |
| 空行 | 通常来自 JSON 末尾 | 否 |

### 5.2 `X文本翻译.txt`

`open` 从 `X文本.txt` 复制而来，结构与原文完全一致。人工翻译时：

- 只改可翻译行（制表符行或含 `\` 的整行）；
- 保留 `当前文件:` 和 `备注:`；
- 不增加、删除、合并行；
- 保存为 UTF-8（无 BOM）。

### 5.3 `行数/X`

与 `X文本.txt` 中的可翻译行一一对应，记录该行在原始 JSON 中的行号：

```text
当前文件:Projects\Steam324\Json_Collected\level3\123-Dialogue.json
	15
	18
当前文件:Projects\Steam324\Json_Collected\level3\124-Other.json
	9
```

行号公式：

```text
行号 = (JSON 文件中的零基行下标 + 1) * 3
```

例如 JSON 的第 0 行（零基）对应行号 3，第 1 行对应 6，第 4 行对应 15。

> 这个 `* 3` 是工具链的固定约定，`save` 和 `load` 必须一致；不要改成真实行号，也不要改公式。

### 5.4 含反斜杠的行

如果 JSON 行包含 `\`（通常是字符串里有转义引号，如 `\"`），`save` 不会按引号拆分，而是把整行原样输出：

```text
	"1 string text": "He said \"hi\".",
```

这种行在 `文本翻译.txt` 中仍然是一整行 JSON。翻译时**必须保持 JSON 语法有效**：引号要转义、逗号保留、字段名不动。`load` 会用译文整行替换原行，而不是替换引号中的值。

### 5.5 `备注` 的三种来源

- `备注:	已经检测到Buddy消息` / `已经检测不到Buddy消息`：根据同一文件中的 `1 UInt8 isBuddy` 字段判断；
- `备注:id:<id>`：来自 `1 string id`；
- `备注:物体名:<name>`：来自 `1 string otherObjectName`。

这些行只用于提示，不参与翻译，也不写入行号表。

## 6. `load` 的 JSON 回写算法

`load` 读取原始 JSON（`当前文件:` 指向的 `Json_Collected` 文件），按行处理：

```text
for 每个 JSON 行下标 c:
    val = (c + 1) * 3
    if val 在 MAP 中:
        if 原始行包含反斜杠:
            输出 MAP[val]（整行译文）
        else:
            把原始行按双引号拆开
            用 MAP[val] 替换第 4 个片段（索引 3）
            重新拼接
    else:
        原样输出
```

MAP 来自：

```text
行号文件中的数字  →  文本文件中的译文行
```

示例：

原始 JSON 行：

```json
  "1 string text": "Hello there.",
```

按 `"` 拆分：

```text
[ "  ", "1 string text", ": ", "Hello there.", "," ]
   0        1              2       3               4
```

替换索引 3：

```json
  "1 string text": "你好。",
```

> 普通行必须保持“字段名 + 冒号 + 引号字符串 + 逗号”的结构；不要改字段名、不要删逗号、不要在值里放未转义的双引号。

## 7. 翻译记忆库 WordLib

### 7.1 键和值

- 键：整行英文（去掉制表符）加上换行，按 UTF-8 编码后的 MD5；
- 值：对应中文译文（加换行）；
- 文件名：`WordLib/<md5>`，无扩展名；
- 文件内容：中文译文 + 换行。

在 Windows 上，脚本以文本模式写入，`\n` 会变成 `\r\n`，所以实际哈希的是：

```text
UTF-8(英文行 + "\r\n")
```

读取时 Python 的通用换行会把 `\r\n` 还原为 `\n`。**不要**用 `strip()` 后的字符串重算 MD5，也不要统一改成 LF，否则词库会全部失效。

### 7.2 构建

`wordlib` / `WORDLIB.py`：

1. 按 `当前文件:` 分组读取 `X文本.txt` 和 `X文本翻译.txt`；
2. 跳过 `备注:`；
3. 逐行配对；
4. 原文 == 译文时跳过（无需记忆）；
5. 原文 != 译文时写入 `WordLib/<md5>`；
6. 已存在的键不覆盖。

如果两组行数不一致，Python 版打印 `读取失败.` 并列出 CH/EN 内容，跳过该文件；此时先修正译文行数。

### 7.3 应用

`usewordlib` / `USEWORDLIB.py`：

1. 选择 `Workspace/` 下以资源名开头的文本文件；
2. 逐行计算 MD5；
3. 命中 `WordLib/<md5>` 时替换为该词库内容；
4. 未命中的行原样保留；
5. 输出：
   - 有 `X文本翻译.txt` → `X_Translated.txt`；
   - 没有 → `X文本翻译.txt`。

词库只做**精确匹配**。以下变化都会导致未命中：

- 英文行增加/删除空格；
- 标点变化；
- `[PLAYER]` 等占位符变化；
- 换行符从 CRLF 变成 LF。

## 8. 百度翻译辅助

### 8.1 配置

`PythonExpansion/APIs/BaiduAPI.txt`：

```json
{
	"APPID": "你的APPID",
	"APPKEY": "你的密钥"
}
```

`T.py` / `TL.py` 读取该文件；缺失或密钥无效时不会翻译。

### 8.2 缓存

- 缓存目录：`PythonExpansion/Translated/`；
- 文件名：查询文本的 MD5；
- 内容：百度返回的译文；
- `地址.txt`：追加记录，格式不严格，仅作参考；
- 命中缓存时不会再请求 API。

### 8.3 `TL.py` 的翻译规则

只翻译满足以下条件的行：

1. 不以 `当前文件:` 或 `备注:` 开头；
2. 去掉空格后，最后一个字符是 `. , ! ? : ; ) ( -` 之一；
3. 不以 `",` 结尾。

不满足的行原样写入 `文本翻译_baidu.txt`。

保护与还原：

| 内容 | 替换为 | 还原 |
| --- | --- | --- |
| `[PLAYER]` 等 `[...]` 占位符 | `§` | 按出现顺序替换回原占位符 |
| 人物名（`TL.py` 中 `banlist` / `banlist2`） | `√` | 按出现顺序还原 |
| `...`、`:)`、`:(` | `■` | 按出现顺序还原 |

如果百度改变了语序，占位符/人名的还原顺序可能错位；机翻结果必须人工检查。

### 8.4 输出

```text
Workspace/<资源>文本翻译_baidu.txt
```

被翻译的行以制表符开头；未翻译的行保持原样。它不会覆盖 `文本翻译.txt`。

## 9. 修订工作流 `REVISE.py`

首次运行会在：

```text
PythonExpansion/Documents/Revision/<资源>/
├─ 0/          # 原文（来自 文本.txt）
├─ 1/          # 人工译文（来自 文本翻译.txt）
├─ 2/          # 百度译文（来自 文本翻译_baidu.txt）
└─ Process.txt # 进度：Editing / Number
```

生成时按文件拆分，并删除重复内容：

- 人工译文与原文相同 → 删除人工译文文件；
- 百度译文与人工译文相同 → 删除百度译文、人工译文和原文文件（无需再修订）。

交互时，对每一行：

- 显示原文；
- 若人工译文不同，显示 `翻译:...`；
- 否则若百度译文不同，显示 `Baidu:...`；
- 提示输入修订；
- 直接回车采用默认译文；
- 修订写入 `PythonExpansion/Documents/WordLib/<md5>`（修订记忆，**不是**项目 `WordLib/`）；
- 每行更新 `Process.txt`，中断后可继续。

> `REVISE.py` 只记录修订决策，不修改 `Workspace` 中的 `文本翻译.txt`。要生成最终译文，仍需人工把修订写回，或基于修订记忆另行处理。

## 10. TextMesh 文本

TextMesh dump 的行格式示例：

```text
... m_Text Hello world ...
```

（实际行可能包含更多字段，工具只检查按空格拆分后的第三个 token 是否为 `m_Text`。）

### 10.1 `textlib` / `TEXTLIB.py`

- 扫描 `TextMesh/<资源>/*.txt`；
- 对每个 `m_Text` 行，计算整行（含换行）的 MD5；
- 保存原始行到 `TextLib/<md5>`；
- 追加到 `TextMesh/地址.txt`；
- 已存在的 MD5 跳过。

### 10.2 `usetextlib` / `USETEXTLIB.py`

- 重新扫描 `TextMesh/<资源>/*.txt`；
- 对每个 `m_Text` 行计算 MD5；
- 如果 `TextLib/<md5>` 存在且内容与原文不同，替换；
- 只写出至少有一行被替换的文件。

输出目录：

```text
# 批处理版
TextMesh/<资源>_T/

# Python 版
TextMesh/Translated/<资源>_T/
```

### 10.3 `edittextlib`

按地址（MD5）打开 `TextLib/<md5>`，把英文行改成中文，保存；再用 `usetextlib` 应用。因为 TextLib 是全局的，同一行文本在所有 TextMesh 文件中都会被替换。

## 11. 批量处理

### 11.1 `auto`

```text
auto 3-12 0-5
```

循环：

```text
for n in 3..12:
    clearmono level<n>
    filter level<n>
for n in 0..5:
    clearmono sharedassets<n>.assets
    filter sharedassets<n>.assets
```

### 11.2 `auto-t`

```text
auto-t 3-12 0-5
```

循环调用：

```bat
python PythonExpansion\TL.py "%PROJECT_DIR%" level<n>
python PythonExpansion\TL.py "%PROJECT_DIR%" sharedassets<n>.assets
```

所有输出重定向到根目录 `文本们.txt`（覆盖旧内容）。在中文 Windows 控制台下通常是 GBK 编码；用支持 GBK 的编辑器打开，或先转成 UTF-8。

`auto-t.bat` 中原本还调用了 `save` 和 `usewordlib`，但这两行是注释状态，不会执行。

## 12. 重命名、回封与更新

### 12.1 为什么需要重命名

`load` 生成的 JSON 保留了集合时的文件名：

```text
Workspace/level3/123-Dialogue.json
```

回封工具通常要求：

```text
unnamed asset-level3-123.json
```

`rename-a` 去掉 `<pathID>-` 后面的名称，补上 `unnamed asset-<资源>-<pathID>.json`。

### 12.2 两种输出位置

- 批处理：`rename-a Workspace level3` → `Workspace/level3_renamed/`
- Python：`-py RENAME level3` 选 `1` → `Renamed/level3_renamed/`

Python 版目标目录重名时追加 `(1)`、`(2)`，不会覆盖旧结果。

### 12.3 回封

用 UABE/AssetStudio 打开原始 `data.unity3d`，用重命名后的 JSON 替换对应资源，再打包。具体菜单和选项取决于工具版本，本仓库不包含该工具，也不自动执行。

### 12.4 更新游戏

- `Functions/update.bat`：适用于新文件名为 `data1.unity3d` 的情况；删除旧 `data.unity3d`，重命名新文件。
- `PythonExpansion/UPDATE.py`：适用于新文件名为 `data.unity3d-mod` 的情况；删除同名原文件，再去掉 `-mod`。

两者都含硬编码路径，先修改再运行；运行前关闭游戏并备份。

## 13. 数据安全与版本控制

- **备份**：`Projects/`、`data.unity3d`、`MonoBehaviour_All/` 在第一次运行 `clearmono` 前备份。
- **不要提交生成物**：`Projects/`、`Temp/`、`PythonExpansion/Translated/`、`PythonExpansion/Documents/Revision/`、`PythonExpansion/Documents/WordLib/` 都可能很大或包含游戏文本。
- **不要提交密钥**：`PythonExpansion/APIs/BaiduAPI.txt` 填入真实 APPID/KEY 后不要外传。
- **不要并行**：多个脚本共用 `Temp\`，并行会互相删除临时文件。
- **不要随意改编码**：工作文本保持 UTF-8 无 BOM；`.bat` 保持 UTF-8 + CRLF；`文本们.txt` 是 GBK 日志。
- **重新导出前**：`save` 会覆盖 `X文本.txt` 和 `行数/X`，但不会覆盖 `X文本翻译.txt`；仍然建议先备份整个 `Workspace/`。
