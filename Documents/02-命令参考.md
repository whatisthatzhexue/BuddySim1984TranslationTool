# 命令参考

本文按功能分组说明 `Functions/` 中的批处理命令和 `PythonExpansion/` 中的 Python 脚本。第一次使用建议先看 [01-快速开始.md](01-快速开始.md)。

## 1. 命令是怎么执行的

### 1.1 启动器 `开始.bat`

双击 `开始.bat`，或在仓库根目录的 `cmd` 中执行：

```bat
开始.bat
```

启动器会：

1. 设置控制台为 UTF-8（`CHCP 65001`）；
2. 读取 `当前项目.txt` 第一行作为 `PROJECT_DIR`（默认 `Projects\New`）；
3. 显示 `备忘录.txt`；
4. 在 `指令:` 提示符下读取输入，按空格拆成最多 4 个 token；
5. 如果 `Functions\<第一个token>.bat` 存在，就 `call` 它，并把后 3 个 token 作为 `%1` `%2` `%3` 传入；
6. 如果没有同名 `.bat`，就把整行输入交给 `call %INPUT%`，也就是直接执行 CMD 命令。

因此：

- **参数不能包含空格**；项目名、资源名、文件名都不要用空格。
- 可以输入 CMD 内建命令，例如 `dir`、`md Projects\New`、`cd`。
- **拼错命令可能被当成 CMD 命令执行**；`remove`、`update`、`del` 等破坏性操作前先确认。
- `h` 和 `manage` 不检查工作目录是否存在；其他命令要求 `PROJECT_DIR` 目录存在，否则提示：

  ```text
  错误:工作目录不存在.请输入manage命令修改工作目录.
  ```

### 1.2 直接调用批处理

不经过启动器时，需要自己设置 `PROJECT_DIR` 环境变量：

```bat
cmd /c "set PROJECT_DIR=Projects\Steam324 && call Functions\save.bat level3"
```

### 1.3 直接调用 Python

Python 脚本统一以仓库根目录为工作目录，参数约定：

```bat
python PythonExpansion\<脚本>.py "<PROJECT_DIR>" <资源> [其他参数]
```

例如：

```bat
python PythonExpansion\SAVE.py "Projects\Steam324" level3
```

### 1.4 通过 `-py` 调用

```text
-py <脚本名> [参数]
```

`Functions\-py.bat` 会提示 `参数:`，然后执行：

```bat
python PythonExpansion\<脚本名>.py "%PROJECT_DIR%" "<参数>"
```

- `<脚本名>` 不含 `.py`，例如 `SAVE`、`TL`、`RENAME`。
- 只能传**一个**参数；需要多个参数时用 `-py CODING`，或直接运行 `python`。
- 脚本名不存在时，会列出 `PythonExpansion\*.py` 中所有可用脚本。

## 3. 基础命令

### 3.1 `manage`

```text
manage <项目名>
```

切换工作区。

- **前置条件**：`Projects/<项目名>/` 已存在。
- **行为**：把 `Projects/<项目名>` 写入 `当前项目.txt`，并把当前会话的 `PROJECT_DIR` 设为该路径。
- **输出**：`当前工作目录:Projects/<项目名>\`。
- **注意**：`manage` 不会创建目录；不存在时输出 `无效路径.`。可以先在启动器里执行 `md Projects\<项目名>`，或在资源管理器中创建。

示例：

```text
manage Steam324
```

### 3.2 `h`

```text
h
```

分三屏显示帮助（基础命令、进阶命令、TextMesh），每屏后按任意键继续。帮助文本在 `Functions/h.bat` 中，是工具的命令契约之一。

### 3.3 `view`

```text
view
```

列出 `%PROJECT_DIR%\Workspace\*`，包括文件（`文本.txt`、`文本翻译.txt` 等）和子目录（`行数`、各资源目录）。用于确认当前工作区有哪些文件。

### 3.4 `edit`

```text
edit
```

用 `notepad.exe` 打开根目录的 `备忘录.txt`。备忘录会在每次启动 `开始.bat` 时显示，适合记录翻译约定、人名对照和易错句。

### 3.5 `change`

```text
change <命令名>
```

用 Notepad++ 打开 `Functions/<命令名>.bat`，例如：

```text
change save
```

**前置条件**：`Functions/<命令名>.bat` 存在；Notepad++ 路径正确（见 `Functions/change.bat`）。

### 3.6 `web`

```text
web <单词>
```

用 Edge 打开有道词典：

```text
https://dict.youdao.com/result?word=<单词>&lang=en
```

- 只取第一个参数，多词短语请直接在浏览器中查询。
- Edge 路径写死在 `Functions/web.bat`，不在默认位置时需要修改。

## 4. 资源准备

### 4.1 `clearmono`

```text
clearmono <资源>
```

按 `清除名单.txt` 删除 `MonoBehaviour_All/<资源>` 中不需要处理的 MonoBehaviour 文本 dump。

- **前置条件**：`MonoBehaviour_All/<资源>/` 已存在；`清除名单.txt` 每行一个类型名（如 `SpriteLayerInfo`、`MessageBox`）。
- **行为**：遍历目录中的文件，按文件名中 `-` 后面的部分匹配类型名；命中则删除。
- **输出**：每个类型一行 `已清除 <资源> 中 N 个<类型>.`。
- **副作用**：直接删除文件，不可恢复；先备份 `MonoBehaviour_All/`。
- **注意**：匹配依赖导出文件名格式。如果文件名带有 `.txt` 后缀而名单没有，或名单行尾有空白，可能匹配不到；可以用 Python 版 `FILTER.py`（按文本内容筛选，不依赖清除名单）替代。

示例：

```text
clearmono level3
```

### 4.2 `filter`

```text
filter <资源>
```

过滤 `MonoBehaviour_All/<资源>`，把真正包含可翻译文本的文件复制到 `MonoBehaviour/<资源>`。

**批处理版**（`Functions/filter.bat`）：

- 逐行扫描文本 dump；
- 识别 `string text = "..."`、`string data = "..."`、`string targetString = "..."`；
- 取值的第一个词，与 `黑名单.txt` 做不区分大小写的比较；
- 只要有一个值不在黑名单中，就复制整个文件；
- 使用 `Temp\test.tmp` / `Temp\notblack.tmp`，需要 `Temp\` 存在。

**Python 版**（`PythonExpansion/FILTER.py`）：

- 读取 `PythonExpansion/Documents/Textsign.txt` 作为字段白名单；
- 读取 `PythonExpansion/Documents/Banlist.txt` 作为首词黑名单（小写）；
- 支持直接调用时传第三个参数 `1`，处理 `MonoBehaviour_All` 下所有子目录：

  ```bat
  python PythonExpansion\FILTER.py "Projects\Steam324" level3 1
  ```

- 如果结果为空，会删除空的 `MonoBehaviour/<资源>` 目录。

**输出**：逐文件 `进度...通过检查.` / `未通过.`，最后 `过滤完成.得到文件数 N.先前为 M.`。

示例：

```text
filter level3
-py FILTER level3
```

### 4.3 `collect`

```text
collect <资源>
```

根据 `MonoBehaviour/<资源>/` 中的文件名，收集对应的 JSON dump。

- **前置条件**：`MonoBehaviour/<资源>/`、`Json/<资源>/` 已存在。
- **命名规则**：
  - MonoBehaviour 文件名：`<pathID>-<名称>.txt`；
  - JSON 文件名：`unnamed asset-<资源>-<pathID>.json`；
  - 输出：`Json_Collected/<资源>/<pathID>-<名称>.json`。
- **行为**：取文件名第一个 `-` 前的数字作为 pathID，复制对应 JSON；目标目录不存在时创建。
- **输出**：`复制完成.应复制N个文件.`；全部成功时提示 `所有文件全部成功复制.`，否则列出缺失文件（批处理写入 `Temp/notfound.tmp`，Python 打印后删除）。
- **注意**：如果 JSON 文件的命名不符合 `unnamed asset-<资源>-<pathID>.json`，需要修改脚本或先改名。

示例：

```text
collect level3
-py COLLECT level3
```

### 4.4 `rename-a`

把 JSON 文件名恢复成回封工具需要的 `unnamed asset-<资源>-<pathID>.json`。

**批处理版**：

```text
rename-a <顶层目录> <子目录>
```

- 源：`%PROJECT_DIR%\<顶层目录>\<子目录>\*.json`；
- 目标：`%PROJECT_DIR%\<顶层目录>\<子目录>_renamed\unnamed asset-<子目录>-<pathID>.json`；
- 示例：`rename-a Workspace level3`，输出到 `Workspace/level3_renamed/`。
- 目标目录已存在时，`md` 会报错，`copy` 可能询问是否覆盖；建议先用 Python 版或清理旧目录。

**Python 版**：

```text
-py RENAME <子目录>
```

- 运行后选择来源：`1.Workspace` 或 `2.Json_Collected`；
- 目标：`%PROJECT_DIR%\Renamed\<子目录>_renamed\`；
- 如果目标目录已存在，自动使用 `_renamed(1)`、`_renamed(2)` 等后缀，避免覆盖；
- 打印每个 `源 -> 目标` 的映射。

**注意**：通常在 `load` 之后对 `Workspace/<资源>` 执行，得到回封用的 JSON；不要对原始 `Json_Collected` 做破坏性操作。

## 5. 文本导出与翻译

### 5.1 `save`

```text
save <资源>
```

从 `Json_Collected/<资源>/` 提取可翻译文本，输出：

```text
Workspace/<资源>文本.txt
Workspace/行数/<资源>
```

**前置条件**：

- `Json_Collected/<资源>/` 已存在（先 `collect`）；
- `%PROJECT_DIR%\Workspace\` 根目录已存在（脚本不会创建根 Workspace，只创建 `Workspace\行数\`）；
- Python 版还需要 `Textsign.txt`、`Banlist.txt` 和 `Temp\`。

**输出格式**：

```text
当前文件:Projects\Steam324\Json_Collected\level3\123-Dialogue.json
备注:	已经检测到Buddy消息
	Hello, [PLAYER]!
备注:id:Dialogue_01
备注:物体名:Buddy
```

- `当前文件:` 标记下一个 JSON 文件；
- `备注:` 是提示，不是翻译单元；
- 以制表符开头的行是待翻译文本；
- 含反斜杠的 JSON 行会原样输出（不带制表符），在 `load` 时按整行替换。

**行号文件** `Workspace/行数/<资源>` 与文本中的翻译单元一一对应，行号公式为：

```text
行号 = (JSON 文件中的零基行下标 + 1) * 3
```

**注意**：`save` 会覆盖已有的 `X文本.txt` 和 `行数/X`；不会覆盖 `X文本翻译.txt`。重新导出前备份人工翻译。

示例：

```text
save level3
-py SAVE level3
```

### 5.2 `open`

```text
open <资源>
```

- 如果 `Workspace/<资源>文本翻译.txt` 不存在，从 `Workspace/<资源>文本.txt` 复制一份；
- 用 Notepad++ 打开 `X文本翻译.txt`；
- 不会覆盖已存在的翻译文件。

**前置条件**：`save` 已生成 `X文本.txt`；Notepad++ 路径正确。

示例：

```text
open level3
```

### 5.3 `wordlib`

```text
wordlib <资源>
```

从「英文原文」和「人工译文」构建翻译记忆库。

- **输入**：
  - `Workspace/<资源>文本.txt`（原文）；
  - `Workspace/<资源>文本翻译.txt`（人工译文）。
- **行为**：
  - 按 `当前文件:` 分组，逐行配对；
  - 跳过 `备注:` 行；
  - 只保存原文与译文不同的行；
  - 键为「原文行（去掉制表符）+ 换行」的 MD5，值为译文；
  - 已存在的键不覆盖。
- **输出**：`Projects/<项目名>/WordLib/<md5>`；控制台打印进度和 `词库更新完毕.`。
- **注意**：两个文件的行数/顺序必须一致；Python 版在不一致时会打印 `读取失败.` 和 CH/EN 内容并跳过该文件。

示例：

```text
wordlib level3
-py WORDLIB level3
```

### 5.4 `usewordlib`

```text
usewordlib <资源> [文件名]
```

用翻译记忆库生成译文。

- **输入**：`Workspace/` 下以 `<资源>` 开头的文本文件；如果只有一个，自动使用；如果有多个，提示输入文件名（不含后缀）。
- **输出**：
  - 如果 `Workspace/<资源>文本翻译.txt` 存在：写入 `Workspace/<资源>_Translated.txt`；
  - 如果不存在：写入 `Workspace/<资源>文本翻译.txt`。
- **行为**：逐行计算 MD5，命中 `WordLib/<md5>` 就替换；未命中的行保持不变。若译文不含双引号，会在行首加制表符。
- **注意**：只做精确匹配；不会改动词库；重复运行会用最新词库覆盖输出文件。

示例：

```text
usewordlib level3
usewordlib level3 level3文本
-py USEWORDLIB level3
```

### 5.5 `checkwordlib` / `editwordlib`

```text
checkwordlib
editwordlib
```

按英文原文查询词库：

1. 提示 `输入英文文本:`；
2. 用 `certutil` 计算 `Temp\TEXT.tmp` 的 MD5；
3. 在 `Projects/<项目名>/WordLib/<md5>` 中查找；
4. `checkwordlib` 打印译文；`editwordlib` 用记事本打开该词库文件，保存后再次打印。

**注意**：

- 输入必须与 `文本.txt` 中的原文行完全一致（包括标点、空格、`[占位符]`），脚本会自己补换行；
- 不要输入 `&`、`|`、`<`、`>` 等 CMD 特殊字符，`echo` 会把它们当语法；
- 需要 `Temp\` 存在。

### 5.6 `textcheck`

```text
textcheck <路径>
```

查看 TextMesh 文本 dump 中的 `m_Text` 行。

- `<路径>` 相对 `PROJECT_DIR`，例如 `TextMesh\level3`；
- 逐个文件打印文件名，并输出第三个空格分隔 token 为 `m_Text` 的行；
- 使用 `Temp\TEMP.tmp`，需要 `Temp\` 存在。

示例：

```text
textcheck TextMesh\level3
```

## 6. 回写与校验

### 6.1 `load`

```text
load <资源> [文件名]
```

把译文按行号写回 JSON。

- **输入**：
  - `Workspace/<文件名>.txt`（人工译文或 `_Translated.txt`）；
  - `Workspace/行数/<资源>`（行号表）。
- **输出**：`Workspace/<资源>/<pathID>-<名称>.json`。
- **行为**：
  - 逐行扫描译文本；`当前文件:` 切换当前 JSON；
  - 对每个可翻译行，按行号找到原 JSON 行；
  - 普通行：按 `"` 分割后替换第 4 个片段（索引 3）；
  - 含 `\` 的行：直接用译文整行替换；
  - 结束后删除 `Temp\` 中的临时文件。
- **前置条件**：`Workspace/<资源>/` 目录可由脚本创建；`Workspace/行数/<资源>` 存在；文本行数与 `save` 时一致。
- **注意**：不要增加/删除/合并译文行；否则行号错位，JSON 会改错或损坏。

示例：

```text
load level3
load level3 level3_Translated
-py LOAD level3
```

### 6.2 `examine`

```text
examine <资源>
```

用 `fc` 对比：

```text
Workspace/<资源>/*.json
Json_Collected/<资源>/*.json
```

- **前置条件**：两边文件名一致（`load` 会保留 `<pathID>-<名称>.json`）。
- **输出**：`全部N个文件通过测试.` 或 `完成.总检查数N.通过数M.`。
- **注意**：
  - 有差异是正常的，只应出现在你翻译的字符串上；
  - `examine.bat` 通过匹配英文 `no differences encountered` 计数；中文版 Windows 的 `fc` 输出可能是本地化文本，导致通过数误报为 0。此时直接看 `fc` 输出或使用 JSON 校验。
  - 需要 `Temp\` 存在。

示例：

```text
examine level3
```

### 6.3 `remove`

```text
remove <资源>
```

🗑️ 删除 `Workspace/<资源>/` 下的所有文件。

- **前置条件**：目录存在。
- **输出**：`已清除 <资源> 的 N 个文件.`。
- **注意**：没有确认提示；执行前确保已经 `rename-a` 备份或已导入回封工具。

示例：

```text
remove level3
```

## 7. TextMesh 文本

TextMesh 文本与 MonoBehaviour 分开处理：`textlib` 建立「整行 → 译文」的文本库，`usetextlib` 把库中的译文应用到 `TextMesh` dump。

### 7.1 `textlib`

```text
textlib <资源>
```

- **输入**：`TextMesh/<资源>/*.txt`；
- **行为**：逐行按空格拆分，若第三个 token 是 `m_Text`，计算整行（含换行）的 MD5；
- **输出**：
  - `Projects/<项目名>/TextLib/<md5>`：保存原始整行；
  - `TextMesh/地址.txt`：追加 `md5` 和原行；
  - 已存在的 MD5 跳过。
- **前置条件**：`TextMesh/<资源>/` 已导出；`TextLib` 会自动创建；需要 `Temp\`。

示例：

```text
textlib level3
-py TEXTLIB level3
```

### 7.2 `usetextlib`

```text
usetextlib <资源>
```

- **输入**：`TextMesh/<资源>/*.txt`、`TextLib/`；
- **行为**：逐行检查 `m_Text` 行；如果 `TextLib/<md5>` 存在且内容与原文不同，替换为库中的译文；
- **输出**：
  - 批处理版：`TextMesh/<资源>_T/<文件名>`；
  - Python 版：`TextMesh/Translated/<资源>_T/<文件名>`；
  - 只写出至少有一行被替换的文件。
- **注意**：两版输出目录不同；后续回封时用对应目录。

示例：

```text
usetextlib level3
-py USETEXTLIB level3
```

### 7.3 `edittextlib`

```text
edittextlib
```

- 提示 `请输入地址:`；
- 地址是 `TextLib/<md5>` 中的 MD5；
- 打印当前内容，用记事本打开，保存后再次打印；
- 把英文行改成中文，再用 `usetextlib` 应用到所有匹配行。

**注意**：TextLib 是全局的，修改一条会影响所有引用同一行的 TextMesh 文件。

## 10. Python 扩展

### 10.1 通用约定

- 工作目录必须是仓库根目录；
- `sys.argv[1]` 为 `PROJECT_DIR`；
- `sys.argv[2]` 为资源名（如 `level3`）；
- 部分脚本使用 `sys.argv[3]`；
- 需要 `requests` 的脚本：`T.py`、`TL.py`；
- 需要 `Temp\` 的脚本：`COLLECT.py`（缺失时写日志）、`SAVE.py`、`LOAD.py`、`WORDLIB.py`、`USEWORDLIB.py`、`TEXTLIB.py`、`USETEXTLIB.py`、`REVISE.py`。

### 10.2 脚本一览

| 脚本 | 直接调用示例 | 作用 |
| --- | --- | --- |
| `CODING.py` | `python PythonExpansion\CODING.py "Projects\Steam324"` | 交互式多命令解释器 |
| `COLLECT.py` | `... COLLECT.py "Projects\Steam324" level3` | 收集 JSON |
| `FILTER.py` | `... FILTER.py "Projects\Steam324" level3 [1]` | 过滤文本 |
| `LOAD.py` | `... LOAD.py "Projects\Steam324" level3 [文件名]` | 回写 JSON |
| `PREFIX_CATCH.py` | `... PREFIX_CATCH.py "Projects\Steam324"` | 生成 Textsign 候选 |
| `RENAME.py` | `... RENAME.py "Projects\Steam324" level3 [1/2]` | 恢复资源命名 |
| `REVISE.py` | `... REVISE.py "Projects\Steam324" level3` | 逐行修订 |
| `SAVE.py` | `... SAVE.py "Projects\Steam324" level3` | 导出文本/行号 |
| `T.py` | `... T.py "Projects\Steam324" "Hello"` | 单句百度翻译 |
| `TEXTLIB.py` | `... TEXTLIB.py "Projects\Steam324" level3` | 构建 TextLib |
| `TL.py` | `... TL.py "Projects\Steam324" level3` | 批量百度翻译 |
| `UPDATE.py` | `... UPDATE.py "Projects\Steam324"` | 更新游戏目录 |
| `USETEXTLIB.py` | `... USETEXTLIB.py "Projects\Steam324" level3` | 应用 TextLib |
| `USEWORDLIB.py` | `... USEWORDLIB.py "Projects\Steam324" level3 [文件名]` | 应用 WordLib |
| `WORDLIB.py` | `... WORDLIB.py "Projects\Steam324" level3` | 构建 WordLib |

### 10.3 `CODING.py`

交互式批命令解释器，适合一次执行多个 Python 步骤。

```text
-py CODING
```

输入规则：

- 命令格式：`脚本名(参数1,参数2)`；
- 一行多个命令用分号 `;` 分隔；
- 输入单个句号 `.` 结束并执行；
- 脚本名不要带 `.py`，大小写按文件名（Windows 文件系统通常不区分大小写）；
- 参数按逗号拆分，不能包含逗号；
- 每个命令最终展开为：

  ```bat
  python PythonExpansion\<脚本名>.py "<PROJECT_DIR>" "<参数1>" "<参数2>" ...
  ```

示例：

```text
SAVE(level3);FILTER(level3)
TL(level3)
.
```

注意：`CODING.py` 只使用 `sys.argv[1]`；通过 `-py CODING` 时提示的“参数”会被忽略。

### 10.4 `TL.py` 与 `T.py`

**`TL.py`**：批量机翻一个资源的 `文本翻译.txt`。

```bat
python PythonExpansion\TL.py "Projects\Steam324" level3
```

- 输入：`Workspace/level3文本翻译.txt`；
- 输出：`Workspace/level3文本翻译_baidu.txt`；
- 只翻译「去掉空格后以 `. , ! ? : ; ) ( -` 结尾」的行，且跳过以 `",` 结尾的行；
- `[占位符]`、人物名、`...`、`:)`、`:(` 会被保护后还原；
- 结果缓存在 `PythonExpansion/Translated/<md5>`，重复查询不会再次请求；
- API 配置在 `PythonExpansion/APIs/BaiduAPI.txt`。

**`T.py`**：单句查询并打印。

```bat
python PythonExpansion\T.py "Projects\Steam324" "Hello there."
```

输出：

```text
Hello there. -> 你好。
```

适合在翻译时快速查词/查句；结果同样会写入缓存。

### 10.5 `REVISE.py`

逐行修订辅助工具。

```bat
python PythonExpansion\REVISE.py "Projects\Steam324" level3
```

首次运行时：

- 在 `PythonExpansion/Documents/Revision/<资源>/` 下生成 `0/`、`1/`、`2/` 三套按文件拆分的文本：
  - `0`：原文（`文本.txt`）；
  - `1`：人工译文（`文本翻译.txt`）；
  - `2`：百度译文（`文本翻译_baidu.txt`）；
- 删除重复内容，减少需要人工看的行；
- 写入 `Process.txt` 记录进度（`Editing`、`Number`）。

交互时：

- 显示原文、人工译文（若有）、百度译文（若有）；
- 提示输入修订；直接回车采用默认译文；
- 修订结果保存到 `PythonExpansion/Documents/WordLib/<md5>`（**独立于项目内的 `WordLib/`**）；
- 每行保存一次进度，中断后可继续。

注意：

- 它**不会**自动改写 `Workspace` 中的译文文件，只记录修订决策；
- 需要 `Workspace/<资源>文本.txt`、`文本翻译.txt`、`文本翻译_baidu.txt` 三者存在；首次运行会读取它们；
- 如果 `Revision/<资源>/` 已存在但 `Process.txt` 不存在，`os.makedirs` 可能报 `FileExistsError`；删除该目录或补建 `Process.txt` 后重试。

### 10.6 `PREFIX_CATCH.py`

扫描 `MonoBehaviour_All/`，生成 `Textsign` 候选。

```bat
python PythonExpansion\PREFIX_CATCH.py "Projects\Steam324"
```

- 输出：`PythonExpansion/Documents/Textsign_catch.txt`；
- 格式：`string <字段名>=<样例文本>`；
- 需要先创建 `PythonExpansion/Documents/`；
- 生成结果需要人工筛选，删除 `string id`、`string otherObjectName` 等非对话字段，再保存为 `Textsign.txt`。

### 10.7 TextMesh 的两个 Python 脚本

- `TEXTLIB.py`：与批处理版 `textlib` 等价，输出 `TextLib/<md5>` 和 `TextMesh/地址.txt`。
- `USETEXTLIB.py`：与批处理版 `usetextlib` 功能相同，但输出到 `TextMesh/Translated/<资源>_T/`，而不是 `TextMesh/<资源>_T/`。

### 10.8 `UPDATE.py`

```bat
python PythonExpansion\UPDATE.py "Projects\Steam324"
```

- 不读取 `PROJECT_DIR` 参数的实际内容；
- 扫描硬编码游戏目录中的 `*-mod` 文件；
- 删除同名原文件，再去掉 `-mod` 重命名；
- 使用前修改脚本顶部的 `Game_Path` 并备份。
