# 常见问题

本文按问题类型列出常见报错、原因和解决办法。命令细节见 [02-命令参考.md](02-命令参考.md)，文件格式见 [03-工作流与数据结构.md](03-工作流与数据结构.md)。

## 1. 启动与路径

### 1.1 `错误:工作目录不存在.请输入manage命令修改工作目录.`

原因：`当前项目.txt` 指向的目录不存在，或 `manage` 写入的路径无效。

解决：

1. 确认 `Projects/<项目名>/` 存在；不存在就先创建：

   ```text
   md Projects\Steam324
   ```

2. 执行：

   ```text
   manage Steam324
   ```

3. 检查 `当前项目.txt` 第一行是否为 `Projects\Steam324`（不要带末尾反斜杠，不要带空格）。

### 1.2 `manage` 提示 `无效路径.`

`manage` 只接受已存在的 `Projects/<项目名>/`，不会自动创建。先创建目录，再执行 `manage`。

### 1.3 双击 `开始.bat` 一闪而过

在 `cmd` 中从仓库根目录运行，看看具体报错：

```bat
cd /d "E:\MyData\游戏项目\1984Translation"
开始.bat
```

常见原因是 Python 不在 PATH、`Temp`/`Workspace` 缺失，或 `.bat` 被保存成了带 BOM 的 UTF-8 / ANSI。

### 1.4 `'python' 不是内部或外部命令`

Python 没有加入 PATH。安装时勾选 “Add Python to PATH”，或把 `Functions\-py.bat` 中的 `python` 改为完整路径，例如：

```bat
"C:\Python311\python.exe" PythonExpansion\%1.py "%PROJECT_DIR%" "%INPUT%"
```

### 1.5 `python: can't open file 'PythonExpansion\...': [Errno 2] No such file or directory`

当前目录不是仓库根目录。所有 Python 脚本都假设工作目录是仓库根目录，因为脚本里使用 `Temp\`、`PythonExpansion\`、`Projects\` 等相对路径。

解决：

```bat
cd /d "E:\MyData\游戏项目\1984Translation"
python PythonExpansion\SAVE.py "Projects\Steam324" level3
```

### 1.6 `系统找不到指定的路径。`

通常是以下目录缺失：

| 缺失目录 | 影响的命令 |
| --- | --- |
| `Temp\` | `filter`、`save`、`load`、`examine`、`wordlib`、`textlib`、`textcheck`、`REVISE.py` |
| `Projects/<项目名>/Workspace\` | `save`（脚本只创建 `Workspace\行数`，不创建 Workspace 根目录） |
| `PythonExpansion\Documents\` | `PREFIX_CATCH.py`、`FILTER.py`、`SAVE.py`、`REVISE.py` |

手动创建：

```text
md Temp
md PythonExpansion\Documents
md Projects\Steam324\Workspace
```

### 1.7 参数里有空格

`开始.bat` 用 `for /f "tokens=1-4"` 按空格拆分输入，路径/文件名带空格会被拆成多个参数。

解决：

- 项目名、资源名、文件名不要用空格；
- 必须带空格时，直接用 `python` 调用脚本并加引号，例如：

  ```bat
  python PythonExpansion\SAVE.py "Projects\My Project" level3
  ```

### 1.8 仓库路径包含中文

当前仓库示例路径 `E:\MyData\游戏项目\1984Translation` 含中文。工具在 `CHCP 65001` 下通常可以处理，但批处理的 `for /f` 对中文和特殊字符较敏感。若遇到莫名其妙的问题，可以把仓库复制到纯 ASCII 路径（如 `E:\1984Translation`）再试。

## 2. 资源导出与筛选

### 2.1 `clearmono` 一个文件也没删

可能原因：

- `清除名单.txt` 的类型名与实际文件名不一致；
- 文件名带 `.txt` 后缀，而名单没有；
- 名单行尾有空格/制表符；
- 导出的文件名中 `-` 的位置与脚本假设不同。

排查：

1. 打开 `MonoBehaviour_All/<资源>/`，看实际文件名；
2. 打开 `清除名单.txt`，确认每行只有类型名，没有多余空格；
3. 如果仍然不匹配，改用 Python 版 `FILTER.py`，它按文本内容筛选，不依赖清除名单。

> `clearmono` 是直接删除，执行前必须备份 `MonoBehaviour_All/`。

### 2.2 `filter` 全部“未通过”

批处理版：

- `Temp\` 不存在 → `Temp\test.tmp` 无法创建，所有文件都会被判为未通过；
- `黑名单.txt` 首词匹配过宽，把文本都排除了；
- 文本 dump 中没有 `string text = `、`string data = `、`string targetString = ` 这三种格式；
- 文件编码不是 UTF-8，导致 `for /f` 读取异常。

解决：

```text
md Temp
```

然后先用一个文件测试，检查文本 dump 的字段行格式；必要时改用 Python 版。

### 2.3 `FILTER.py` 报 `FileNotFoundError: ...Textsign.txt` 或 `Banlist.txt`

Python 版需要：

```text
PythonExpansion/Documents/Textsign.txt
PythonExpansion/Documents/Banlist.txt
```

创建方法见 [01-快速开始.md](01-快速开始.md) 第 3 节。`Textsign.txt` 可以先运行 `-py PREFIX_CATCH` 生成候选，再人工整理。

### 2.4 `FILTER.py` 结果为空并提示 `已清除空文件夹.`

说明没有文件通过白名单/黑名单组合。检查：

- `Textsign.txt` 是否包含实际字段名（注意是 `string text`，不是 `1 string text`）；
- `Banlist.txt` 是否把对话首词也排除了；
- 文本 dump 的 ` = ` 分隔符是否与脚本一致；
- 先用单个文件手动跑一遍逻辑。

### 2.5 `collect` 提示缺少文件

原因：MonoBehaviour 文件名中的 pathID 与 `Json/` 中的 JSON 文件名不匹配。

检查：

```text
MonoBehaviour/<资源>/123-Dialogue.txt
Json/<资源>/unnamed asset-<资源>-123.json
```

- 两边 pathID 必须一致；
- JSON 文件名必须是 `unnamed asset-<资源>-<pathID>.json`；
- `<资源>` 目录名必须一致（包括 `sharedassets0.assets` 这样的后缀）。

可以用 `list-a` 逐个核对：

```text
list-a Json_Collected level3
```

### 2.6 `save` 输出为空

可能原因：

- `Json_Collected/<资源>/` 为空；
- Python 版 `Textsign.txt` 字段名不匹配；
- `Banlist.txt` 过宽；
- JSON 文件的字段结构不是 `"1 string text": "..."` 形式。

先打开一个 `Json_Collected` 文件，确认字段名和格式，再对照 `Textsign.txt`。

## 3. 翻译与词库

### 3.1 `open` 打不开 Notepad++

`Functions/open.bat` 和 `change.bat` 写死了：

```text
D:\Program Files\Notepad++\notepad++.exe
```

改成你的安装路径，或直接用记事本：

```bat
notepad.exe "%PROJECT_DIR%\Workspace\%1文本翻译.txt"
```

### 3.2 `WORDLIB.py` 报 `读取失败.` 并打印 CH/EN

原因：`X文本.txt` 与 `X文本翻译.txt` 的行数/顺序不一致。

检查：

- 没有增加/删除/合并译文行；
- `备注:` 行没有被删除；
- `当前文件:` 行数量一致；
- 文件没有被编辑器自动格式化。

修复后重新运行 `wordlib`。

### 3.3 `wordlib` 生成 0 条记录

可能原因：

- 译文与原文完全相同（脚本跳过相同行）；
- 两个文件的行没有按顺序对应；
- 译文行前面多了/少了制表符，导致配对偏移；
- `WordLib/` 已存在旧记录，脚本不覆盖。

先看 `WordLib/` 目录是否有文件；再检查 `X文本翻译.txt` 是否只改了可翻译行。

### 3.4 `usewordlib` 提示 `请输入要加载的文件名(不含后缀):`

`Workspace/` 下有多个以资源名开头的文本文件（`文本`、`文本翻译`、`文本翻译_baidu`、`_Translated` 等）。输入要使用的那一个，例如：

```text
level3文本翻译
```

或直接传参：

```text
usewordlib level3 level3文本翻译
```

### 3.5 `usewordlib` 输出的是 `_Translated.txt` 而不是 `文本翻译.txt`

这是预期行为：

- 如果 `X文本翻译.txt` 已存在，脚本不想覆盖人工译文，所以写 `X_Translated.txt`；
- 如果不存在，才写 `X文本翻译.txt`。

用哪一份都可以 `load`，只要行数一致。

### 3.6 `checkwordlib` 说文件不存在，但词库里有译文

原因通常是输入文本与原文不完全一致。注意：

- 标点、空格、大小写、`[PLAYER]` 都要一致；
- 不要输入 `文本.txt` 行首的制表符（脚本会自己加换行，但不要带 tab）；
- 不要有行尾空格；
- `echo` 对 `&`、`|`、`<`、`>` 等特殊字符会出错，含这些字符的文本请用 Python 直接计算 MD5 查询。

可以把 `文本.txt` 中的那一行复制出来，去掉行首制表符后再输入。

### 3.7 翻译记忆突然全部失效

检查是否：

- 把 `文本.txt` / `文本翻译.txt` 从 CRLF 转成了 LF，或反之；
- 用编辑器保存时加了 BOM；
- 修改了英文原文的空格/标点；
- 把 `WordLib/` 复制到了另一台机器但文件被转换过。

WordLib 的键是「英文行 + 换行」的 MD5；上述变化都会改变键。不要用 `strip()` 后的文本重算，也不要用 LF 统一换行。

## 4. 百度翻译

### 4.1 `找不到API。`

`PythonExpansion/APIs/BaiduAPI.txt` 不存在或路径不对。确认文件位于：

```text
PythonExpansion\APIs\BaiduAPI.txt
```

并填入合法的 JSON：

```json
{
	"APPID": "你的APPID",
	"APPKEY": "你的密钥"
}
```

### 4.2 `ModuleNotFoundError: No module named 'requests'`

```bat
pip install requests
```

如果使用虚拟环境，确认 `-py` 调用的 `python` 就是安装了 `requests` 的那个。

### 4.3 `KeyError: 'trans_result'` 或程序中断

脚本没有对百度错误做完整容错。常见原因：

- APPID/APPKEY 错误；
- 未开通通用翻译服务；
- 额度用完；
- 请求频率过高；
- 网络无法访问百度 API；
- 文本含百度不支持的字符。

排查：

1. 用 `T.py` 单独查一句，观察返回；
2. 检查百度控制台的额度、IP 白名单、应用状态；
3. 把 `TL.py` 中的 `r.json()` 临时打印出来，看 `error_code` / `error_msg`；
4. 修复后重新运行；已缓存的句子不会重复请求。

### 4.4 `TL.py` 几乎什么都没翻译

`TL.py` 只翻译满足以下条件的行：

- 不以 `当前文件:` / `备注:` 开头；
- 去掉空格后，最后一个字符是 `. , ! ? : ; ) ( -`；
- 不以 `",` 结尾。

游戏文本中有很多行以引号、括号或其他字符结尾，会被跳过。可以：

- 人工翻译这些行；
- 临时放宽 `TL.py` 的 `cantrans` 判断（改代码后注意回归测试）；
- 用 `T.py` 单句翻译后手工粘贴。

### 4.5 占位符或人名被翻译/错位

`TL.py` 只保护：

- `[...]` 形式的占位符；
- `banlist` / `banlist2` 中硬编码的人物名；
- `...`、`:)`、`:(`。

新人物名或新占位符需要手动加入 `TL.py` 的列表。百度改变语序时，`§` / `√` / `■` 的还原顺序可能错位，机翻结果必须人工核对。

### 4.6 想清除百度翻译缓存

缓存位于：

```text
PythonExpansion/Translated/
```

删除对应 MD5 文件即可重新请求；删除整个目录会清空所有缓存。`地址.txt` 只是记录，不影响缓存命中。

## 5. `load`、`examine` 与 JSON

### 5.1 `load` 生成的 JSON 内容错位

原因：`文本翻译.txt` 的行数与 `save` 时不一致，导致行号表错位。

修复：

- 从备份恢复 `X文本翻译.txt`，只修改可翻译行；
- 不要增加/删除/合并行；
- 不要删除 `当前文件:` / `备注:`；
- 重新 `save` 会覆盖 `X文本.txt` 和 `行数/X`，但不会恢复译文；先备份。

### 5.2 `load` 后 JSON 不合法

常见原因：

- 在含 `\` 的整行翻译中破坏了 JSON 语法（引号、逗号、转义）；
- 在普通行的译文里放了未转义的双引号；
- 行号错位，把译文写进了字段名或其他结构。

检查：

```bat
python -m json.tool "Projects\Steam324\Workspace\level3\123-Dialogue.json" >nul
```

如果报错，用原始 `Json_Collected` 文件对比，恢复后重做。

### 5.3 `load` 把文件写到了奇怪的位置

`LOAD.py` 中有：

```python
os.makedirs(os.getcwd() + "\\" + WORKSPACE_DIR + dir_name)
```

它假设 `PROJECT_DIR` 是相对路径（`Projects\...`）。如果你把 `PROJECT_DIR` 设成绝对路径，可能拼出重复路径。保持 `manage` 写入的相对路径即可。

### 5.4 `examine` 显示“通过数 0”，但文件其实一样

`examine.bat` 解析 `fc` 输出中的英文提示：

```text
no differences encountered
```

中文版 Windows 的 `fc` 可能输出本地化提示，导致脚本数不到“通过”。这时：

- 直接运行 `fc` 对比单个文件；
- 或用 Python 计算文件哈希/内容比较；
- 不要仅凭 `通过数 0` 判断文件有问题。

### 5.5 `examine` 报大量差异

预期差异只应出现在翻译过的字符串。如果差异过多：

- 检查是否 `load` 了错误的文件（例如 `文本翻译_baidu` 而不是人工译文）；
- 检查是否有行号错位；
- 检查 `save` 之后是否重新导出过 `Json_Collected`，导致行号变化；
- 用文本对比工具查看具体差异。

### 5.6 `remove` 删除了文件，能恢复吗

不能。`remove` 没有回收站，直接删除 `Workspace/<资源>/*`。

预防：

- 先 `rename-a`，确认 `Renamed/` 中有输出；
- 或手动复制 `Workspace/<资源>/`；
- 执行前确认资源名正确。

## 6. 重命名、回封与更新

### 6.1 `rename-a` 提示覆盖/卡住

批处理版 `rename-a` 在目标目录已存在时仍会 `copy`；如果文件同名，`copy` 可能询问是否覆盖，导致批处理暂停。

解决：

- 优先用 Python 版 `-py RENAME`，它会自动追加 `(1)`、`(2)`；
- 或先删除/移走旧的 `_renamed` 目录；
- 或在 `copy` 命令上加 `/Y`。

### 6.2 `RENAME.py` 输出目录带 `(1)`

目标目录已存在，Python 版为避免覆盖自动追加后缀。确认使用最新目录，或清理旧的 `Renamed/<资源>_renamed*`。

### 6.3 回封后游戏没有变化

检查：

- 导入的 JSON 文件名是否为 `unnamed asset-<资源>-<pathID>.json`；
- 是否导入到了正确的资源包；
- 是否重新打包并替换了游戏目录中的 `data.unity3d`；
- 是否改的是正确的 `level`/`sharedassets`；
- 游戏是否使用了缓存或另一个数据文件。

先用一个明显的字符串测试，确认回封流程本身可用。

### 6.4 `update` 失败或游戏打不开

`update.bat` 会删除旧 `data.unity3d` 再重命名；`UPDATE.py` 会删除同名原文件。操作不可逆。

解决：

1. 关闭游戏；
2. 从备份恢复 `data.unity3d`；
3. 检查新文件是否完整、文件名是否匹配；
4. 修改脚本中的硬编码路径后再试。

### 6.5 `update.bat` / `UPDATE.py` 找不到文件

它们使用作者本机路径：

```text
C:\Users\用户\Desktop\Translate\...
```

换成你的游戏数据目录，并确认：

- `update.bat` 需要 `data1.unity3d`；
- `UPDATE.py` 需要 `*-mod` 文件；
- 路径中含空格时保留引号。

## 7. TextMesh

### 7.1 `textlib` 找不到任何 `m_Text` 行

检查：

- 导出的 TextMesh 文件是否在 `TextMesh/<资源>/*.txt`；
- 行按空格拆分后，第三个 token 是否确实是 `m_Text`；
- 文件是否为 UTF-8；
- 是否有隐藏字符/BOM。

`textcheck TextMesh\<资源>` 可以快速查看识别到的行。

### 7.2 `usetextlib` 没有输出文件

原因：

- `TextLib/` 为空；
- `TextLib/<md5>` 内容与原文相同（脚本只在不同时替换）；
- TextMesh 行的 MD5 与建库时不一致（文件被修改/换行变化）；
- 输出目录不同：批处理是 `TextMesh/<资源>_T`，Python 是 `TextMesh/Translated/<资源>_T`。

先 `edittextlib` 修改一条 TextLib 记录，再运行 `usetextlib` 测试。

### 7.3 `edittextlib` 说文件不存在

地址必须是 `TextLib/<md5>` 中的 MD5，可以从：

- `TextMesh/地址.txt`；
- `textlib` 的输出日志；
- `TextLib/` 目录文件名

获取。不要输入完整路径或带 `.txt` 的名字。

## 8. `REVISE.py`

### 8.1 首次运行报缺少文件

`REVISE.py` 首次运行需要同时存在：

```text
Workspace/<资源>文本.txt
Workspace/<资源>文本翻译.txt
Workspace/<资源>文本翻译_baidu.txt
```

先完成 `save`、`open`，并运行 `TL.py` 生成百度译文；如果不想用百度译文，可以复制一份人工译文或空文件作为 `文本翻译_baidu.txt`（需保持行数一致）。

### 8.2 `FileExistsError: [WinError 183]`

通常是 `PythonExpansion/Documents/Revision/<资源>/` 已存在，但 `Process.txt` 不存在（上次中断/手动删除）。解决：

- 删除该 `Revision/<资源>/` 目录后重跑；
- 或手动创建 `Process.txt`：

  ```text
  Editing:0
  Number:0
  ```

### 8.3 修订后译文没有变化

`REVISE.py` 只把修订写入：

```text
PythonExpansion/Documents/WordLib/<md5>
```

它不会修改 `Workspace` 中的 `文本翻译.txt`。需要你根据修订记录更新译文，或自行写脚本把修订记忆合并进项目 `WordLib/`。

### 8.4 如何从中断处继续

重新运行：

```bat
python PythonExpansion\REVISE.py "Projects\Steam324" level3
```

脚本读取 `Process.txt` 中的 `Editing` / `Number`，提示是否继续（`Y`/`N`）。选 `N` 可以重新指定文件和行号。

## 9. 编码与换行

### 9.1 `文本们.txt` 打开是乱码

它是 `auto-t` 的控制台输出重定向文件，中文 Windows 下通常是 GBK。用 Notepad++ 选择“编码 → 中文 → GB18030/GBK”打开，或转成 UTF-8 后再看。

### 9.2 编辑 `.bat` 后中文乱码/命令失效

- 保存为 **UTF-8 无 BOM**；
- 保持 CRLF 换行；
- 不要保存为 ANSI/GBK（启动器 `CHCP 65001` 会按 UTF-8 解释）；
- 不要给 `@echo off` 前加 BOM，否则 CMD 可能把 BOM 当成命令的一部分。

### 9.3 文本文件带 BOM

`LOAD.py` / `SAVE.py` 用 `encoding='utf-8'` 读取，不会自动去掉 BOM。如果 `文本翻译.txt` 带 BOM，第一行 `当前文件:` 可能变成 `\ufeff当前文件:`，导致文件分组失败。

解决：用编辑器另存为“UTF-8 无 BOM”。

### 9.4 WordLib 键对不上

确认没有做以下操作：

- 把文件从 CRLF 转成 LF；
- 用 `strip()`/`rstrip()` 预处理英文行；
- 改变行首制表符；
- 在英文行末尾加空格。

哈希的是“英文行 + 换行”的字节，任何变化都会改变 MD5。

## 10. 批处理与自动化

### 10.1 `-py` 只能传一个参数

`Functions\-py.bat` 只读取一个 `参数:`。需要多参数时：

- 直接用 `python`：

  ```bat
  python PythonExpansion\FILTER.py "Projects\Steam324" level3 1
  ```

- 或用 `-py CODING`：

  ```text
  FILTER(level3,1)
  .
  ```

### 10.2 `auto` / `auto-t` 处理范围不对

参数格式是 `<起始>-<结束>`，用空格分隔两组：

```text
auto 3-12 0-5
```

- 第一组是 `level` 编号；
- 第二组是 `sharedassets` 编号（脚本自动加 `.assets`）；
- 编号必须是从小到大的十进制整数。

### 10.3 `auto-t` 覆盖了 `文本们.txt`

`auto-t.bat` 使用 `>` 重定向，每次运行都会覆盖上一次的日志。需要保留就先复制一份。

### 10.4 批处理里的特殊字符

`echo %string%` 对 `&`、`|`、`<`、`>`、`^`、`%` 等字符敏感；`for /f` 对引号、逗号、分号也有解析规则。文本中出现这些字符时，优先用 Python 脚本处理，不要在批处理提示符里直接输入。

## 11. 最后一次检查

遇到无法定位的问题时，按这个顺序排除：

1. 是否在仓库根目录运行？
2. `PROJECT_DIR` 是否正确、是否存在？
3. `Temp\`、`Workspace\`、`PythonExpansion\Documents\` 是否创建？
4. 资源目录名、pathID、JSON 文件名是否匹配？
5. 文本行数是否与 `save` 时一致？
6. 文件是否为 UTF-8 无 BOM、换行是否被改过？
7. 是否有备份可以回滚？

如果仍然无法解决，保留以下信息再排查：

- 完整报错文本；
- 执行的命令和当前 `当前项目.txt`；
- 相关目录的文件列表；
- 出问题的中间文件（`文本.txt`、`文本翻译.txt`、`行数`、JSON）各一小段。
